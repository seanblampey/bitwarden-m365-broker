# Bitwarden M365 Broker Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Claude Code plugin whose local MCP server signs in to Microsoft 365 with admin logins from Bitwarden and runs Graph / Exchange Online calls for Claude, without any secret reaching Claude.

**Architecture:** A TypeScript MCP server (stdio) owns everything secret: it drives the `bw` CLI, shows native Windows dialogs for unlock and approval, automates Microsoft sign-in in a hidden Edge via Playwright, keeps tokens in memory, and returns only redacted results. A `PreToolUse` hook stops Claude from going around it. Pure logic (redaction, classification, hook rules, TOTP/PKCE, vault, tokens, broker) is unit-tested on Linux with fakes; sign-in is tested against a local fake login site; Windows-only pieces get a manual checklist.

**Tech Stack:** Node 20+, TypeScript (ESM, `strict`), `@modelcontextprotocol/sdk`, `zod`, `playwright-core` (Edge channel on Windows; preinstalled Chromium in tests), `otpauth`, `vitest`. PowerShell (Windows PowerShell 5.1 or pwsh 7) for dialogs and Exchange.

**Spec:** `docs/superpowers/specs/2026-11-24-bitwarden-m365-broker-design.md`

## Global Constraints

- Windows 10/11 only at runtime; Claude Code runs locally as the same user.
- No secret (master password, login password, TOTP seed/code, access/refresh token, `BW_SESSION`) in any tool result, error, log, or process command line. Secrets go to child processes only via env or stdin.
- Allowlist = items in Bitwarden folder `Claude Access`; item name = alias; custom field `tenant` = tenant domain.
- TOTP generated by the broker from the seed (never `bw get totp`).
- Reads pass without approval: Graph `GET`; Exchange cmdlets with verb `Get`. Everything else needs a Yes/No dialog that defaults to **No** and is TopMost.
- Never auto-accept a Microsoft consent page; fail with `needs_consent`.
- One broker per Claude Code session; vault idle-lock default 30 minutes.
- Nothing persisted to disk except the audit log (`%LOCALAPPDATA%\claude-bw-broker\audit.jsonl`) and the config (`%APPDATA%\claude-bw-broker\config.json`).
- Every MCP tool result passes through `Redactor.scrub`.

## Review Focus

1. **Graph `path` that escapes Graph** (`https://evil.com/x`, `//evil.com`, `@evil.com`, `/../`) — must be rejected so the token is only ever sent to `graph.microsoft.com`. Test in Task 2.
2. **`Get-` cmdlets that aren't Exchange** (`Get-Content`, `Get-ChildItem`, `Get-Process`) — must be refused, or they'd read local files without approval. Test in Task 2 (name rules) and Task 10 (module-origin check in the PowerShell script).
3. **Secrets echoed in errors** — `bw`, the token endpoint, Graph and PowerShell stderr can echo inputs; every error path must be scrubbed. Tests in Tasks 1, 8, 11.
4. **Vault locks mid-task / user cancels the password dialog** — idle lock re-prompts transparently; cancel returns `unlock_cancelled`, not a hang or crash. Test in Task 6.
5. **Incomplete Bitwarden item** (no TOTP seed, no `tenant` field) — clear error naming the missing field, nothing secret. Test in Task 6.

### Task 8: Sign-in automation

**Files:** Create `src/auth/resources.ts`, `src/auth/signin.ts`, `tests/fixtures/fake-login/server.ts`, `tests/signin.test.ts`

**Interfaces — Produces:**
- `interface Resource { key: 'graph' | 'exo'; clientId: string; redirectUri: string; scopes: string[] }`; `graphResource(scopes: string[]): Resource`; `EXO_RESOURCE: Resource`.
  - Graph: clientId `14d82eec-204b-4c2f-b7e8-296a70dab67e` (Microsoft Graph Command Line Tools), redirectUri `http://localhost`.
  - EXO: clientId `fb78d390-0c51-40cd-8e17-fdbfab77341b` (Exchange Online PowerShell), scopes `['https://outlook.office365.com/.default','offline_access']`, redirectUri `https://login.microsoftonline.com/organizations/oauth2/nativeclient`. **Verify both redirect URIs** against current Microsoft docs / MSAL config in the ExchangeOnlineManagement module before relying on them; record the source in a code comment.
- `type SignInCategory = 'wrong_password'|'mfa_not_totp'|'needs_consent'|'conditional_access'|'federated'|'account_locked'|'page_changed'`
- `class SignInError extends BrokerError { category: SignInCategory }` (code `signin_failed`, message is a fixed sentence per category — never page text)
- `interface SignInParams { authority: string; tenant: string; resource: Resource; username: string; password: string; totpSeed: string }`
- `class SignInBrowser { static launch(opts?: { headless?: boolean; channel?: string }): Promise<SignInBrowser>; authorize(p: SignInParams): Promise<{ code: string; verifier: string }>; close(): Promise<void> }` — one in-memory browser context (no `storageState`, no user-data-dir) reused across `authorize` calls so the session cookie gives silent SSO for the second resource.

`authorize` opens `${authority}/${tenant}/oauth2/v2.0/authorize?client_id&response_type=code&redirect_uri&scope&code_challenge&code_challenge_method=S256&prompt=select_account&login_hint=<username>` (`prompt=select_account` omitted if the context already has a session), intercepts any request whose URL starts with `redirectUri` (`context.route` → abort) and extracts `code` (or `error`/`error_description` → map `AADSTS53003`/`AADSTS53000` → `conditional_access`, `AADSTS65001` → `needs_consent`, `AADSTS50053` → `account_locked`, else `page_changed`). Between, a loop (max 60 s overall, 15 s per step) detects the page state and acts:

| Detected by | Action |
|---|---|
| `input[name=loginfmt]` visible | fill username, click `#idSIButton9` |
| host is not the authority host (and not redirect) | throw `federated` |
| `input[name=passwd]` visible | fill password, click `#idSIButton9` |
| `#passwordError` visible | throw `wrong_password` |
| `input[name=otc]` visible | fill `totp(seed)`, click `#idSubmit_SAOTCC_Continue` |
| push / other MFA page (`#idDiv_SAOTCAS_Title`, `[data-value=PhoneAppNotification]`) | click "Sign in another way"/"I can't use…" link (`#signInAnotherWay`, `a#idA_SAASTO_TOTP`), then pick `[data-value=PhoneAppOTP]`; if not offered → `mfa_not_totp` |
| `#idBtn_Back` with KMSI (`#KmsiCheckboxField`) | click `#idBtn_Back` (No) |
| URL contains `/Consent` or `#consentHeader` | throw `needs_consent` (never click accept) |
| account picker tile `[data-test-id="<username>"]` | click it |
